# 하루 회고 · 2026-10-16 로컬 구현·검증

이 문서는 회고 단계의 90/70개 검사 기록입니다. 이후 통계·23시 이월·수동 백업·자동 실행 코드를 포함한 최신 143/102개 검사는 `statistics-rollover-backup-verification-20261016.md`를 따릅니다.

사용자 진행 승인에 따라 잘한 점·아쉬운 점·다음 행동의 세 칸을 구현했다. 기존 개인 기록·실행 중인 앱·마우스는 사용하지 않았다. 다음 시제품은 마지막에 일괄 준비하며 이번에는 실행 묶음·ZIP·공개 GitHub/Vercel을 교체하지 않았다.

## 동작

- 오른쪽 상세에 계획·운동·회고 탭을 제공한다. 세 칸은 모두 선택이며 각 2,000자까지다. 한 칸만 작성하거나 계획·운동 없이 회고만 작성할 수 있다.
- 날짜별 회고는 한 건으로 저장·수정한다. 앞뒤 공백을 정리하되 내용 안의 줄바꿈은 유지한다. 공백뿐인 새 회고는 생성하지 않는다.
- 저장한 회고를 세 칸 모두 비워 저장하면 삭제 확인을 요청한다. 취소하면 현재의 빈 입력을 유지하고 DB의 원래 회고·계획·운동을 바꾸지 않는다. 승인하면 회고만 삭제한다.
- 저장 버튼과 Ctrl+S는 같은 날짜의 계획·운동·회고 변경을 함께 확정한다. 검증·DB 저장이 하나라도 실패하면 모두 반영하지 않고 입력을 보존한다. 성공 후에만 저장 완료를 표시한다.
- 탭·테마·창 숨김/복원에서 세 탭의 입력을 유지한다. 날짜·모드 변경 등에서 미저장 확인을 취소하면 이동하지 않는다. 버림을 선택하면 저장된 값으로 복구한 뒤 이동한다.
- 실제 저장된 회고 날짜의 수를 조회하는 저장 기능을 제공한다. 공백 회고·삭제 회고는 일수에서 제외하고 같은 날 여러 번 수정해도 하루로 센다. 통계 화면은 아직 구현하지 않았다.

## 저장

SQLite 형식 4에 날짜를 기본키로 하는 회고 테이블을 추가했다. 날짜 수정 번호와 저장 트랜잭션은 계획·운동과 공유한다. 이전 수정본의 덮어쓰기를 막으며 뒤쪽 운동 저장에서 오류가 발생해도 회고·계획·수정 번호가 함께 보존된다.

가상 형식 3 DB를 업그레이드해 계획·운동·체중·kcal과 수정 번호가 유지되고 회고가 자동 생성되지 않음을 확인했다. 개인 DB에는 적용하지 않았다. 새 형식은 이전 앱에서 열 수 없으므로 최종 배포에 버전 전환 안내가 필요하다.
