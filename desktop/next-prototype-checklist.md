## 사용자 확인 결과와 이번 변경

창 크기 합격, 칸 간격 정상, 상세의 바깥 크기 유지/비율 적당, 입력 화면 양호, 팝업 위치·표시 양호라는 사용자 결과를 기록했습니다. 합격한 구조는 유지하고 다음만 수정했습니다.

1. 달력 세로 스크롤 제거:4/5/6주가 높이 안에 들어가도록 날짜 칸 한 변을 계산합니다. 같은 월 안에서는 모두 같은 정사각형이며 월별 주 수에 따라 공통 크기는 달라집니다. 상세를 열어 가로 폭이 부족할 때의 가로 스크롤은 유지합니다.
2. 날짜/공휴일 글자 높이: 두 문구 모두 고운돋움을 사용하고 실제 글자 윤곽의 높이·위쪽을 맞춥니다. 두 줄 공휴일도 첫 줄과 마지막 줄이 보입니다. 생일과 겹치면 생일 이름 공간을 우선하고 긴 공휴일은 한 줄 줄임 표시, 전체 이름은 툴팁·상세에서 확인합니다.
3. 앱 글씨1pt 확대: 본문·메뉴·버튼·입력·통계·기념일·팝업·로고·명상 타이머 등을1pt 키웠습니다. 공휴일은 날짜의 실제 보이는 높이에 맞추는 보정을 우선합니다. Windows 파일 선택창·시스템 메시지·제목 표시줄 등 OS 글꼴 설정은 바꾸지 않습니다.

## 이번에 사용자가 다시 볼 것

- [ ] 4주·5주·6주 달을 바꿔도 세로로 움직이지 않고 마지막 주까지 보이는가? 예:2021년2월,2026년10월,2020년8월. 과거 일부 연도에는 공휴일 자료 미포함 안내가 나오는 것이 정상입니다.
- [ ] 2026년10월3일·5일·9일과5월24일의 날짜/공휴일 글자 높이가 자연스러운가? 두 줄 이름도 위아래가 잘리지 않는가?

문제가 있으면 ‘2번:5월24일 첫 줄이 너무 높음’처럼 번호와 화면을 알려 주세요. 이미 확인한 창 크기·비율·팝업 위치를 다시 전체 검사할 필요는 없습니다. 기능 검사는 별도 데이터의 자동 검사와 재실행·트레이 근거를 검증 보고서에 남깁니다.

## 유지되는 동작

기본900×880(DIP) 고정 창, 창 이동·최소화·트레이 숨김·완전 종료, 위치·테마·강조색 기억을 유지합니다. 작은 작업 영역에서만 그 안으로 줄인 고정 크기를 사용합니다. 소형 모드와 항상 위는 없습니다. 날짜 상세·통계는 같은 창 안에서 열고, 긴 입력/목록의 세로 스크롤은 유지합니다.

계획·운동·회고는 저장 버튼 또는 Ctrl+S로 저장합니다. 미완료 계획만23시에 이월하고 운동·회고·기념일은 원래 날짜를 유지합니다. 주간·월간·요일별 통계와 조건이 맞는 운동의 예상 kcal,14일 체중 갱신을 유지합니다. 선택형5분 명상과 오늘의 미완료 할 일 팝업은 언제든 닫습니다.

기념일 원본 연월일·양력/음력·윤달·반복 규칙을 보존합니다. 음력 환산1900~2050년, 공휴일 자료2025~2027년입니다. 형식7·백업v3이며 기존v1/v2백업도 읽습니다. 내보내도 원본 기록은 남고 복원은 확인 후 기록/설정 전체 교체입니다.

시험 실행에서는 Windows 로그인 자동 실행 등록을 차단합니다. 개인 DB·실행 중 앱·OS 설정·GitHub/Vercel을 변경하지 않았습니다. 새 글씨/배치의 실제 사용자 확인과 다양한 모니터·절전/복귀·장기 사용은 별도입니다. 이번 확인 후 최종 Git 업로드 자료를 정리합니다.
