# 통계·23시 이월·수동 백업 통합 검증 · 2026-10-16

기존 회고 단계 이후의 로컬 구현 기록이다. 사용자 승인에 따라 정해진 기능을 연속 구현했다. 개인 DB·실행 중인 앱·마우스·현재 Windows 시작 항목은 변경하지 않았다. 이전의 90/70개 검사 기록은 당시 단계의 증거로 유지한다.

## 구현 범위

| 기능 | 현재 동작 |
|---|---|
| 통계 | 같은 앱의 별도 본문. 주간·월간·요일별, 이전/다음/현재 기간과 요일별 최근 28일·이번 달·직접 기간 선택. 월요일 시작 |
| 지표 | 배정 날짜 기준 계획/완료율, 운동 기록·일수·시간·평균, 회고 일수, 계산된 기록만의 예상 kcal과 포함 건수. 분류/종목 합계 |
| 그래프·필터 | 완료 계획·운동 일수·시간·kcal 지표 선택. 운동 분류/종목 필터는 운동 수치에만 적용. 숫자와 그래프가 같은 결과를 사용 |
| 비교 | 종료된 기간은 이전 전체 기간, 진행 중 기간은 같은 진행 지점까지 비교. 이전 달 길이를 보정하고 양쪽 일수 표시. 완료율은 %p, 일수/시간은 절대 차이. 계산 없는 kcal은 증감 제외 |
| 실행 날짜 | 완료 체크 시 선택일 제안, 수정에서 실제 완료일 변경. 23시 뒤 내일의 계획 완료에는 현재일/배정일을 함께 보여 확인. 기존 날짜 없는 완료는 요일 집계에서 제외 건수 안내 |
| 23시 이월 | 저장된 미완료 계획의 같은 ID 이동, 시간 해제, 최초일·이전 시간·사유·누락 기준 수 보존. 운동·회고 독립. 늦은 신규 입력은 지난 기준에 소급 포함하지 않음 |
| 편집 보호 | 입력 중인 날짜를 출발·도착 모두에서 보호. 저장/버림 후 재확인. 이전 수정 번호로 이월·복원을 덮어쓰지 못함 |
| 백업 | 수동 JSON v1 파일 내보내기. 성공해도 원본·수정 번호 유지. 임시 사본 작성 완료 후 파일 교체. 자동 백업·병합 없음 |
| 복원 | 파일 검사 → 미저장 보호 → 건수/전체 교체 확인 → 기록·설정 한 트랜잭션. 과거 kcal·체중 이력·이월 정보 유지. 실패/취소 시 변경 없음 |
| 설정 저장 | DB preferences로 이전. 기존 settings.json은 필요 시 읽고 새 저장은 DB 사용. 복원과 기록의 원자성 확보. 명상 표시 날짜는 기기 내역과 합쳐 중복 안내 방지 |
| 로그인 자동 실행 | 현재 사용자 PDSPlanner Run 값에 인용된 exe 경로 등록/해제, 설정에 등록 여부 안내. 검증·별도 데이터 실행에서는 쓰기 차단 |

백업은 32MB, 통계 직접 조회는 100년 이내로 검사한다. 최신 버전이 아닌 백업·알 수 없는 종목/필드·지원하지 않는 kcal 출처 버전은 조용히 바꾸지 않고 거절한다. 누락된 칼로리를 0으로 만들지 않는다. 다른 버전과의 변환기는 구현하지 않았다.

## 검증 결과

- Release 빌드 성공, 경고·오류 0개.
- 코어 **143개**: 기존 90개에 통계·이월·백업·설정·이전 형식 관련 53개 추가. 4계획/3완료=75%, 운동 30+20+40분=90분, 2운동일 평균45분, 회고2일 기준 확인.
- WPF 흐름 **102개**: 기존 70개에 새 기능 32개 추가. 통계 이동 취소, 실제 완료일 수정과 편집 중 체크, 이월 출발일 입력 보호, 복원 취소/잘못된 파일/잘못된 색상/입력 보호/승인 교체 등을 확인.
- 기존 달력 18개 조합에 상단 메뉴 겹침 검사 보강. 회고 6개 테마/크기, 통계 900×620·940×700·1200×900의 마지막 항목 접근 확인. 라이트/다크 통계 PNG도 직접 확인.
- 시험 앱 완전 종료 후 새 프로세스에서 회고 세 칸·계획·운동 유지 확인.
- 백업 복원 뒤쪽에 의도적으로 SQL 오류를 일으켜 기록·수정 번호·설정이 모두 되돌아가는지 검사. 내보내기 오류가 기존 백업 파일을 바꾸지 않는지도 확인.
- 형식 4 가상 DB를 5로 이전해 기존 계획·완료·메모를 유지하고 실제/생성 날짜를 지어내지 않음 확인. 일요일 이월은 다음 주에 한 번 포함.

최종 기능 증거: `artifacts/verification-features-20261016-225116/`의 features.json, review-reopen.json, statistics-layouts.json, presentation.json, review-layouts.json과 PNG. 확인창은 검증용 응답 분기를 사용했고, 실제 Windows 파일 선택창·확인창을 사람이 클릭했다고 표현하지 않는다.

## 성능과 배포

verify-performance.ps1로 별도 기록과 화면 밖 비활성 창을 사용했다. 최종 단기 표본은 `artifacts/verification-performance-20261016-225656/`의 verification.json과 statistics-performance.json이다. 프로세스 CPU 시간 증가를 경과 시간과 8논리 프로세서로 나눈 비율이며, 메모리 단위는 파일의 MB 필드명과 달리 1,048,576바이트로 나눈 MiB다.

| 상태 | Working Set MiB | Private Bytes MiB | 10초 평균 CPU |
|---|---:|---:|---:|
| 일반 | 134.9 | 70.7 | 0.000% |
| 소형 | 138.8 | 72.1 | 0.000% |
| 숨김 | 140.0 | 71.7 | 0.215% |
| 주간 통계 | 150.8 | 77.6 | 0.020% |

일반·소형·통계는 표시/전환 후 각각 20초를 기다린 뒤 10초 측정했다. 0.000%는 해당 표본의 반올림 결과이며 CPU를 전혀 쓰지 않는다는 뜻이 아니다. 준비 중인 명상 타이머는 실행하지 않았고 검증 모드에서는 OS 트레이·자동 이월 예약·시작 항목을 만들지 않는다. 따라서 실제 트레이·23시 작업·명상 진행 중의 비용을 모두 포함한 측정이 아니다.

과거 환경 확인은 Windows 11 Home 10.0.26200 x64, i5-1135G7, 약15.7GiB를 기록했다(environment-and-verification.md). 이번에는 OS 10.0.26200과 8논리 프로세서를 재확인했다. 동시에 실행한 다른 앱을 통제한 비교 실험이 아니며 이번 CIM 하드웨어 재조회는 사용할 수 없어 CPU 모델·총 RAM은 과거 확인값이다.

시작→준비는 이번 실행 3.536초, 창 생성→준비는 2.121초였다. 첫 통계 조회·컨트롤 생성은 약127.9ms였으나 마지막 화면 그리기 완료를 측정한 수치는 아니다. 저장 기록은 계획1건·운동0건인 작은 표본이다. 5회 시작·20회 저장/조회, 5분 CPU 평균/최대, 30분 상주·100회 화면 전환·일반/큰 데이터 검증은 미완료다. 통계 Working Set 150.8MiB는 초기150 목표를 소폭 넘었고 시작도3초를 넘은 표본이 있으므로 최종 성능 목표 합격으로 표시하지 않는다.

이전 표본 `artifacts/verification-performance-20261016-225200/`에서는 통계를 처음 연 뒤 2초 준비/10초 측정 때 CPU1.872%, Working Set166.4MiB였다. 준비 시간을 일반·소형과 같은20초로 늘려 재측정했으며 초기 상승의 원인을 완전히 분리해 규명한 것은 아니다. 이전 측정도 지우지 않는다.

시험용 일괄 묶음은 `artifacts/PDS-Windows-x64-functional-20261016/`에 별도 준비했다. START-TEST.cmd는 개인 기록과 다른 PdsFunctionalPreview 저장소를 사용하고 OS 자동 실행 등록을 차단한다. 기존 artifacts/PDS-preview, 사용자 바탕화면 앱, 공개 GitHub/Vercel은 교체하지 않는다.

최종 코어143개 검사에는 23시 정각 저장과 늦은 신규 입력의 이력 기준 수도 포함한다. 런타임 포함 실행 파일 자체로 **WPF102개와 새 프로세스 복구를 다시 통과**했다. 근거는 `artifacts/verification-candidate-20261016-230238/`의 features.json과 review-reopen.json이다. 프로젝트 SDK의 DOTNET_ROOT 없이 실행했고 마우스·개인 기록은 사용하지 않았다. 실제 파일 선택창·트레이·로그인 조작 검증과는 구분한다.

제공 파일: `artifacts/PDS-Windows-x64-functional-20261016.zip`. 실행 파일·런타임·폰트와 안내/확인 목록·계획서·이 검증 기록을 함께 포함한다. 시험 DB·개인 기록·소스 SDK/캐시는 넣지 않는다. SHA-256 파일과 manifest.json으로 포함 파일을 식별한다.

## 남은 확인과 기능

실제 트레이 아이콘·전경 복원·항상 위·체감 전환, 로그인 자동 실행 등록/해제·경로 변경/제거, 실제 23시·절전/시계 변경·다중 모니터·Windows 셸 재시작, 장기·많은 기록의 성능, 사용자/추가 참여자 검증은 남아 있다. 선택형 타이머의 다음 날 안내와 실제 14일 체중 재입력도 장기 확인 대상이다.

운동 거리·세트·추가 경사/장비 조건, 계획-운동 연결, 별도 실제 실행 메모와 수동 날짜 이동, 태블릿·위젯·동기화는 구현 완료가 아니다. 기존 일반 메모와 회고·자동 이월은 사용할 수 있다. 코드 구조는 부분 파일로 분리했으며 전체 MVVM 전환은 하지 않았다.
