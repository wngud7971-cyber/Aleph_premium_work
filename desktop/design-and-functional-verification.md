# 2026-10-16 · 디자인 반영과 기존 기능 검증

## 변경 범위

Windows WPF 시제품의 기존 캘린더·계획 화면에 소프트 플래너 배치를 반영했다. 브라우저나 WebView는 추가하지 않았다. 고운돋움을 앱 리소스로 포함하고 본문을 12px로 표시한다. 로고와 영어 월 제목은 Georgia 기울임이며 일반 창 20px, 소형 창 17px이다. 분홍 강조색은 #E3BACA이고 선택 날짜·저장 버튼·체크박스에 함께 적용한다. 사용자가 저장한 다른 색상은 유지한다. 앱 내부 표면 모서리는 16px이며 Windows 기본 제목 표시줄·크기 조절은 유지한다.

추가 디자인 수정은 보류하고 기능 검증을 우선한다. 운동·kcal·회고·통계·23시 이월·백업·자동 실행은 이번 변경에서 구현하지 않았다.

## 확인 결과

- Release 빌드·런타임 포함 실행 묶음 생성: 성공, 경고·오류 0개.
- 기존 저장·검증 검사 15개: 통과. 추가·수정·완료·삭제·시간 검증·충돌·트랜잭션 롤백·재연결 등을 포함한다.
- 실제 WPF 실행: 계획 저장 → 완료 저장 → 제목 수정 → 완전 종료 → 별도 프로세스로 재실행 후 같은 기록과 소형 모드 복구를 확인했다.
- WPF 기존 동작 검사: 창 닫기의 숨김 처리, 복원 후 미저장 입력 유지, 테마 변경 중 입력 유지, 빈 제목·거꾸로 된 시간 저장 거부와 입력 유지, 실패 시 DB 내용·버전 유지, 설정 저장을 통과했다.
- 화면: 일반·소형 각각 세 크기와 4·5·6주 달력의 총 18개 조합에서 정사각형 날짜 칸, 건수 글자 높이, 일반 창의 저장 버튼 접근을 검사했다. 작은 창에서 달력 스크롤은 허용한다.
- 글꼴: 실행 중 실제 해석된 폰트 URI가 포함 리소스 GowunDodum-Regular.ttf임을 확인했다. 처음 발견한 기본 Windows 글꼴 적용 문제는 창 스타일을 명시해 수정했다.
- 실제 UI 조작: 날짜 선택, 명상 안내 닫기, 제목 입력, 모드 전환의 미저장 확인과 Escape 취소, 입력 보존, 저장 버튼의 성공 안내, 완료 체크의 미저장 상태, Ctrl+S 저장·집계, 테마 변경 시 입력 보존을 확인했다.

## 검증의 한계

트레이로 숨긴 뒤 Windows 조작 도구가 숨겨진 창을 다시 잡지 못해 트레이 아이콘을 직접 클릭한 복원은 이번 수동 조작에서 완료하지 못했다. 앱 내부 검사에서는 실제 닫기 이벤트와 앱의 복원 함수를 실행해 창 재표시·입력 보존을 확인했다. 이를 트레이 아이콘 조작 전체 검증으로 표시하지 않는다. 검증용 프로세스는 경로와 ID를 확인해 종료했다.

삭제는 저장 계층 검사로 확인했으며 이번 UI 조작에서 삭제 확인창은 누르지 않았다. 여러 화면 배율·모니터, 장시간 상주, 절전 복귀·셸 재시작 검증은 남아 있다. 초기 실행의 짧은 자원 측정은 최종 글꼴 수정 전 결과이므로 이번 실행 묶음의 성능 보증으로 사용하지 않는다.

개인 기록 폴더는 이번 검증에 사용하지 않았다. GitHub·Vercel에는 아직 재게시하지 않았다.

## 추가 수정 · 다크 모드의 선택 날짜와 저장 글자

사용자가 선택 토요일 숫자와 저장 글자가 잘 안 보인다고 보고했다. 선택된 날짜는 테마 패널과 다른 강조색 표면을 쓰므로, 일반 토요일의 밝은 파란색을 그대로 사용하지 않고 강조색 기준으로 따로 계산한다. 분홍 #E3BACA 위의 토요일은 #1C4C91, 일요일은 #9D1D42, 저장 글자는 #211F25이다. 다른 강조색에서는 원래 색을 밝히거나 어둡게 조정해 대비를 확보한다. 다른 달의 선택 날짜는 강조 배경이 없으므로 일반 달력 색을 사용한다.

저장 글자는 공통 TextBlock 스타일이 버튼의 Foreground 상속을 덮어쓰지 않도록 수정하고, 버튼 템플릿에도 글자색 전달을 명시했다. Release 빌드와 19개 검사를 통과했으며 대비 검사는 강조색 125개를 포함한다. 이번 추가 수정에서는 마우스 조작이나 실제 앱 창 실행을 수행하지 않았다. 최종 표시의 실제 사용 확인은 다음 시제품 실행에서 이어간다.
