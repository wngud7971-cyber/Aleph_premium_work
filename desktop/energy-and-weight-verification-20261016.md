# 체중과 예상 kcal · 2026-10-16 로컬 구현·검증

이 문서는 체중·kcal 단계 기록이다. 이후 회고를 포함한 최신 검증과 별도 프로세스 복구는 `review-verification-20261016.md`를 따른다.

기본 운동 입력에 이어 체중 등록·14일 갱신과 예상 kcal을 구현했다. 개인 기록·현재 실행 중인 사용자 앱·마우스를 사용하지 않았다. 기존 ZIP·`artifacts/PDS-preview`·공개 GitHub/Vercel은 교체하지 않았고 다음 시제품에 일괄 반영한다.

## 구현 범위

- 현재 체중은 kg·소수 첫째 자리까지 수동 저장한다. 값을 같게 다시 입력해도 입력일이 갱신된다. 이력을 추가하고 가장 최근 저장한 이력을 현재 기준으로 사용한다.
- 입력일부터 14일이 되는 로컬 날짜부터 새 kcal에 재입력이 필요하다. 입력일이 미래이면 유효한 기본 체중으로 사용하지 않는다. 운동 화면과 설정에서 현재 값·입력일·다음 필수 입력일을 확인한다.
- 기한 경과는 앱 전체를 잠그지 않는다. 운동만 저장하면 kcal은 없음으로 남긴다. 기본 체중과 기록별 적용 체중은 구분하며 과거 기록의 체중만 바꿔도 기본 갱신일은 바뀌지 않는다.
- kcal 사용은 선택이다. 적용 집단 확인, 유효한 기본 체중, 기록별 적용 체중, 수행 시간, 해당 종목의 공식 활동 기준을 확인해 계산한다. 횟수·층수만으로 시간을 추정하지 않는다.
- 입력마다 미리보기를 갱신하고 저장 전에는 DB를 바꾸지 않는다. 정수 표시에 `약`을 붙이며 원래 소수 값·MET·활동 코드·체중·기준 입력일·계산 시간·출처·산식과 간단/상세 입력값을 보존한다.
- 현재 체중 변경·기한 경과·목록 조회만으로 과거 계산을 바꾸지 않는다. 메모만 편집해도 기존 계산을 유지한다. 새 계산의 유효 체중 조건은 저장 계층에서도 확인한다.
- 풋살의 총 참여 시간과 경기 시간을 분리한다. `총 2시간`은 경기 시간을 채우지 않는다. 완료한 20분 주기 수의 15+5 제안은 확인 후 적용하고 직접 수정 가능하다. 경기 구간만 계산한다.
- 날짜별 운동 목록에서 kcal과 계산 포함 건수를 표시한다. 기간 합계용 저장 기능은 원래 소수 값을 더하며 전부 미계산인 경우 NULL이다. 통계 화면은 다음 작업이다.

## 공식 기준과 지원 조건

2026-10-16에 [2024 Adult Compendium](https://pacompendium.com/adult-compendium/)의 19~59세 기준과 활동 표를 확인했다. [공식 정의](https://pacompendium.com/)의 MET 단위를 따라 `MET × kg × 초 / 3600`으로 계산한다. 결과는 해당 시간의 휴식 대사도 포함한 총 소모량의 일반 추정이며 개인 실측값으로 표시하지 않는다.

22개 앱 종목에 공식 활동 항목 50개를 연결했다. 자료의 MET를 수정하거나 서로 다른 강도를 평균해 새 값을 만들지 않는다. 숫자와 한국어 선택 조건은 `Pds.Core/WorkoutEnergy.cs`에 포함하고 출처 버전을 저장한다. 제품은 조회·계산에 인터넷이나 AI를 사용하지 않는다.

| 앱 종목 | 연결한 기준 | 출처 |
|---|---|---|
| 걷기·계단·하이킹 | 평지 걷기 3구간, 계단 이동 5조건, 하이킹 3조건 | [Walking](https://pacompendium.com/walking/) |
| 야외 러닝 | 일반 조깅과 확인한 달리기 속도 3구간 | [Running](https://pacompendium.com/running/) |
| 러닝머신 | 일반 장비·경사 0%의 걷기 3구간. 달리기·곡선형·경사는 미지원 | [Walking](https://pacompendium.com/walking/) |
| 실내 사이클 | 일반과 50W·60W·70~80W·90~100W·101~125W·126~150W | [Bicycling](https://pacompendium.com/bicycling/) |
| 실외 사이클 | 선택한 페이스 3조건과 원문 속도 3구간 | [Bicycling](https://pacompendium.com/bicycling/) |
| 맨몸운동 | 해당 동작이 포함된 체조·체중 저항·줄넘기 기준. 동작 횟수로 강도를 생성하지 않음 | [Conditioning Exercise](https://pacompendium.com/conditioning-exercise/) |
| 구기·라켓 | 풋살, 축구·농구 조건, 배드민턴, 테니스, 탁구, 일반 스쿼시 | [Sports](https://pacompendium.com/sports/) |

간단 선택과 상세 입력 중 한 경로만 사용한다. 상세 속도는 km/h를 원문의 mph로 환산해 대응하며 구간 사이 빈 값은 보간하거나 최근접 값으로 처리하지 않는다. 실내 출력도 검증한 구간만 지원한다. 조건이 없으면 일반 기준으로 조용히 돌아가지 않고 미계산 이유를 표시한다. 속도만 입력하고 경사·짐·장비 조건이 다른 운동에 적용하지 않도록 화면 안내를 둔다.

계단은 현재 선택한 이동 구간의 층수를 기록한다. 오름·내림 각각의 별도 입력 칸, 거리·세트·추가 출력·러닝머신 달리기/경사/곡선형 장비·계획 연결은 아직 구현하지 않았다.

## 저장·업그레이드

SQLite 형식 3에 체중 이력과 운동별 경기 시간·계산 입력·계산 스냅샷을 추가했다. 기존 운동을 삭제할 때 계산 행도 같은 트랜잭션에서 제거한다. 저장 오류가 나면 계획·운동·계산 일부만 반영하지 않는다. 소수는 JSON과 문자열의 decimal 값으로 보존하고 기간 합계도 decimal로 더한다.

형식 1 계획과 형식 2 운동의 가상 DB를 업그레이드해 기존 시간·메모·완료·수정 번호와 시간 없는 층수 기록을 보존했다. 이전 운동에 kcal을 채워 넣지 않는다. 새 형식 DB는 이전 앱으로 열 수 없으므로 최종 배포 시 버전 전환 안내가 필요하다. 이번에는 개인 DB를 업그레이드하지 않았다.

## 검증 결과

- Release 빌드 성공, 경고·오류 0개. 코어 검사 **74개 통과**: 이전 42개에 체중·kcal 검사 32개 추가.
- WPF 흐름 **51개 통과**: 이전 29개에 체중·kcal 미리보기·저장·갱신·입력 보호·실제 저장 버튼 검사 22개 추가. 기존 18개 창 크기/달력 배치 조합도 포함한다.
- 체중은 13일째 유효/14일째 만료, 미래 입력일, 같은 값 재입력, 잘못된 소수 자리, 저장·재열기와 과거 계산 보존을 검사했다. 실제 14일 동안 사용한 결과와 구분한다.
- 70kg 보통 걷기 30분은 133kcal. 풋살 90분 경기 819kcal, 75분 경기 682.5kcal→약 683kcal. 총 2시간만 입력하면 미계산이다.
- 실내 사이클 50W는 4.0 MET, 100W는 6.0 MET. 미지원 55W에는 계산값을 만들지 않았다. 실내 기준의 실외 오적용, 숨긴 상세 값의 간단 경로 오적용을 검사했다.
- 원래 kcal을 합산한 후 한 번 반올림하며 미계산은 0으로 취급하지 않는다. 계산값과 산식이 불일치하면 저장을 거부한다.
- 실제 체중 저장 버튼에서 소수 둘째 자리 입력 거부·입력 유지와 정상 저장 완료 안내를 확인했다. 반복 검사 중 2초 폴링 방식의 완료 확인이 실패한 기록은 남겼다. 검사 대기를 실제 저장 Task 완료로 바꾼 뒤 최종 74/51개 검사를 통과했다. 이를 개인 기록 유실 또는 실제 저장 실패로 단정하지 않는다.
