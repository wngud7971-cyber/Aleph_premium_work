# 첫 시제품 검증 기록

확인일: 2026-10-15. Windows 11 x64, i5-1135G7, 메모리 약 16GB 환경의 Release 실행 파일을 사용했습니다.

## 확인한 기능

- 날짜 선택 → 계획 입력 → 수동 저장 → 완료 저장 → 제목 수정 → 종료 → 새 프로세스로 재실행해 기록 보존 확인.
- 일반·소형 모드의 정사각형 날짜 칸과 소형 모드 복원.
- 독립된 임시 DB 검사 15개: 최초 저장, 재연결 복구, 입력 검증, 매개변수 SQL, 완료·삭제 건수, 수정 시 ID 유지, 충돌 거부, 트랜잭션 실패 시 원본 보존, 날짜 범위, 더 새로운 DB 형식 보호.

## 마지막 초기 성능 표본

| 상태 | Working Set (MiB) | Private Bytes (MiB) | 평균 CPU |
|---|---:|---:|---:|
| 일반 창 + 상세 | 139.7 | 72.4 | 0.000% |
| 소형 모드 | 143.5 | 71.0 | 0.000% |
| 트레이 숨김 | 145.4 | 72.8 | 0.234% |

일반 창 준비 후와 소형 모드 전환 후 각각 20초를 두고 상태별로 10초 평균 CPU를 읽었습니다. CPU는 논리 프로세서 8개의 전체 용량 대비 비율입니다. 메모리는 각 구간 끝의 값이며 강제 GC나 작업 집합 비우기를 하지 않았습니다. 계획 1건을 추가·수정·완료 처리한 상태였고 입력 커서가 깜빡이지 않는 버튼에 포커스를 두었습니다. 이미지 저장은 측정 후 수행했습니다.

앞선 실행에서는 Working Set 약 148~167MiB와 전환 직후 CPU 상승도 관찰했습니다. 마지막 값만으로 일정한 상한이나 다른 앱보다 가볍다는 결론을 내리지 않습니다. 5분 평균·최댓값, 시작 5회, 30분 상주, 대량 데이터, 여러 화면 배율 검증은 남아 있습니다.

측정 뒤 캡처의 투명 배경 합성을 보완했고 새 실행 파일로 저장 기록·창 모드 복구와 정사각형 칸을 다시 확인했습니다. 이후 성능 표본을 새로 수집하지는 않았습니다.

## 현재 한계

이 버전은 계획 기록 중심의 첫 시제품입니다. 운동·kcal·회고·통계·23시 이월·백업/복원은 아직 구현 전입니다. 웹 화면 초안의 예시 기능과 실제 Windows 구현 범위를 구분해야 합니다.
